# 邮箱右侧分类栏来源调查

调查日期：2026-11-04。依据用户时光服截图及本机已安装插件源文件，只读检查，未改动其他插件。本机客户端为 3.80.2.70522 / Interface 38002。

## 定位结论与证据

截图中的发件箱右侧窄图标列，与 EasyAuction 3.5.24 的“闪寄”分类快捷附件栏位置、图标分类顺序一致。其模块为 `Modules/Mail/ComposeRuntime.lua`，分类模型为 `Modules/Mail/QuickAttachController.lua` 中的 `ItemCategoryRegistry`，物品读取为 `Modules/Mail/BagScanner.lua`。

- ComposeRuntime 从 ItemCategoryRegistry 取得分类，在邮箱右侧创建竖排图标；点击后按类别加入附件。
- 同插件 InboxView 为“闪收”创建相关分类过滤栏，显示时的位置不同于发件页。
- BGLite 的 SendMail 模块负责“批量”标签，不是这列专业／材料图标的实现。
- NDui 的邮箱模块有联系人列表与皮肤处理；该文件未发现此分类模型。本次通过源码与截图对应定位，未在游戏里执行 /fstack 作运行时归属确认。

## 数据从哪里来

它不提供逐物品、逐配方的专业需求数据库。分类规则用游戏 API 返回的 `classID`、`subclassID`，例如布料、皮革、金属矿石、草药、附魔材料等贸易品子类；另外包含宝石、药水等分类。图标由游戏法术图标或预设游戏纹理提供。

BagScanner 通过 GetItemInfoInstant（或 C_Item 同名 API）读取物品大类、子类，再交给类别匹配；未发现该分类路径联网抓取物品或配方数据。每类默认收件人属于它自己的用户配置，不是物品分类数据库。

QuickAttachController 的注释声明前 15 类的顺序与 ID 参考 Postal QuickAttach 的 Cata/Mists 分支。这是本机代码自己的来源声明，尚未逐项核对上游当前版本；Postal 官方项目的发行记录确实包含 [QuickAttach 模块](https://www.wowace.com/projects/postal/files/5454386)。不能将旧分支分类表直接视为所有当前客户端通用。

## 是否可作为本项目数据来源

### 与本插件的功能重合（2026-11-04 再次核对）

重合明显：背包扫描、按类筛选、快速添加原生附件、每类默认收件人，都覆盖了日常材料邮寄的部分需求。若玩家只需把整类草药／矿石寄给固定小号，现有侧栏已经可以满足，不应宣称本插件在这一路径有本质差异。

本插件当前的区别在于按目标角色已记录的专业进行筛选、基于客户端配方材料关系匹配同一物品的多个专业、独立用户归属规则及按物品选择数量。所检查的 EasyAuction 侧栏匹配路径只使用物品类别，不查询收件角色的专业，也不使用配方反向材料索引。这是对已检查模块的结论，不代表其整个插件不存在其他角色或规则管理功能。

产品方向建议：将本插件重点维持在“选择角色 → 按专业判断实际材料用途 → 个人规则修正 → 邮寄”，避免继续扩展通用邮件批量收取、拍卖功能，减少与现有工具重复。

结论：适合作为“游戏物品分类”的调查线索，不替代现有材料与专业关系数据。

- 可直接使用游戏 API 的大类／子类事实，为今后的“布料／矿石／草药／用品”筛选提供依据。应独立实现，并分别核对各客户端分类枚举。
- 同一类别的物品并不一定属于同一专业，元素材料尤其可能跨多个专业；分类无法回答具体哪些配方消耗某物品。
- 钓鱼用品、专业工具等非配方物品仍需额外的用途数据，不能假定这列分类已经覆盖。
- 继续保留本项目各客户端的 DB2 专业消耗关系及用户覆盖。未来若研究 Postal 数据，需要另行确认具体分支、许可和兼容范围。

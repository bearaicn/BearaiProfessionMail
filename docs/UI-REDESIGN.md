# 0.2.0 界面改造分析与实施计划

日期：2026-11-04。依据：用户游戏截图、本机已安装 RurutiaSuite 4.7.0 源码、InboxMailBag 源码和当前插件实现。用户同意后已实现 0.2.0，实际布局为 640×644、角色表格 4 个可见行、材料网格 11 列×3 行；本文件保留原设计依据，验证与部署状态以 PROGRESS.md 和 progress.json 为准。

## 当前问题与已获证据

- 用户截图确认 0.1.0 已能显示邮箱入口和助手主界面。入口与邮箱顶部控件重叠，助手高透明背景降低文字可读性。
- 助手通过 CreateFrame、BackdropTemplate、UIPanelButtonTemplate 等原生 API／模板创建，属于插件自己的界面。截图中的邮箱外观可能受其他皮肤插件影响，未核实当前实际皮肤提供者。
- 角色前后循环、专业分类循环不适合查找；材料按大行排列，空间利用率低；未选角色时只有空白列表，缺少明确空状态。

## 露露工具箱只读分析

## 推荐界面

独立实现轻量控件层，不要求安装露露、NDui 或 ElvUI。默认深色高不透明面板、细边框、浅色正文、弱化说明和统一强调色；职业信息使用职业颜色，同时保留文字。首版不引入庞大 UI 框架。

邮箱旁采用上下结构，参考宽 640、高 620 个 UI 单位，最终尺寸以游戏 UI 缩放和实际可用区域验证。右侧空间不足时尝试左侧，再采用安全缩放／可移动窗口；不能只依赖 SetClampedToScreen 导致窗口回推遮挡原生附件区。具体断点与尺寸需游戏内确认。

1. 顶栏：名称、版本、收起／关闭，保留简短操作提示。
2. 角色区：搜索、添加／编辑／删除、刷新当前角色；固定表头和可滚动数据行。
3. 表格列：角色、职业、等级、专业；服务器在角色名下一行，来源用本账号／手动标识，避免挤占多列宽度。专业过多时截断并 Tooltip 展开。点击整行选中，高亮保留。
4. 收件目标摘要和自动填写勾选项：始终区分筛选目标与原生收件人，刷新不覆盖玩家手改。
5. 材料工具条：名称／ID 搜索、专业下拉、规则管理。下拉默认“全部已学专业”，仅列所选角色的专业；切换角色时无效筛选自动重置。
6. 材料区：约 10 列、4 行的背包格子，最终按可用宽度计算列数；右下角数量，品质细边框，锁定变暗，悬停真实背包 Tooltip。保留真实 bag/slot，不合并相同材料堆叠，拖拽仍走现有安全检查。
7. 底栏：匹配堆叠数／数量统计、分页或滚动状态，以及由玩家在原生邮箱发送的简短提示。

空状态分别说明：尚未选择角色、目标未记录专业、无匹配材料、搜索无结果；不让空白区承担所有状态。

## 邮箱入口

用户红框在底部标签行，现有“邮包”来自 InboxMailBag，不应占用或移动它。其 InboxMailBag.lua 会动态创建 MailFrameTabN，使用 MailFrame.numTabs 并在空间不足时调整标签位置。

采用独立“材料”切换按钮，视觉接近标签，定位到最后一个可见邮箱标签右侧并留间距；不会伪装成新的原生邮件页，不增加 MailFrame.numTabs、不替换 MailFrameTab_OnClick。空间不足则在标签行下方放置入口。邮箱显示与布局变化后重新计算位置，测试默认邮箱和 InboxMailBag 组合；不修改其他插件文件。

## 数据与文件改动计划

- 新增 UI/Theme.lua：颜色、字体、边框、间距统一定义。
- 新增 UI/Widgets.lua：按钮、输入框、带滚动菜单的下拉、滚动表格基础、物品格子；使用两客户端均可核实的 Frame API。
- 修改 UI/MainFrame.lua：布局、背景、窗口位置、编辑弹层与空状态。
- 修改 UI/CharacterList.lua：删除循环角色操作，替换为可搜索、滚动、可点击的表格。基础名称排序，可补职业／等级表头排序。
- 修改 UI/MaterialGrid.lua：替换列表为真实格子，下拉筛选、品质与数量角标；保留拾取链路。
- 修改 UI/MailButton.lua：底部标签避让、独立切换状态及位置更新。
- 修改 Modules/CharacterManager.lua 与 Core/Init.lua：记录 UnitLevel，监听 PLAYER_LEVEL_UP 更新；手动编辑允许选职业和可选等级。旧记录缺字段显示“未知”，不填 0、不猜其他账号信息。
- Core/Compatibility.lua：如需职业显示、品质颜色或框架差异，在兼容层隔离。InventoryScanner 按需传递品质字段。
- SavedVariables：仅增加可选 class／level 字段，读取兼容旧记录，schema 维持 1；无需清空用户数据，无外部数据库变更。
- TOC 更新加载顺序，UI 功能迭代目标 0.2.0；源码和双客户端配置继续共用主线。
- 更新 tests/mock.lua、tests/behavior.lua、部署检查、README、TESTING 和进度记录。

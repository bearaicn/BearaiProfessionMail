# 功能完整度与后续范围

更新日期：2026-11-04，测试版0.5.0。

## 当前判断

核心功能已基本实现，可以进入功能冻结与游戏验收阶段。不能标记正式完成：最近的附件拆分、首次入口、跨插件兼容和二次分类仍有真实游戏待验项目。三客户端模拟通过不等于三客户端游戏通过；用户对经典旧世0.3.2的历史确认不自动覆盖当前版本。

| 能力 | 实现与自动验证 | 真实游戏边界 |
| --- | --- | --- |
| 当前角色／专业、手动角色管理 | 已实现及模拟验证 | 各客户端完整复验待完成 |
| 客户端独立专业材料数据 | 三套对应构建索引、来源与哈希齐全 | 隐藏／未开放配方尚未剔除，专业用品覆盖仍可扩充 |
| 用户规则维护、来源和覆盖 | 独立面板，用户规则优先，明确排除生效 | /reload持久化和新增类别列表需验收 |
| 背包筛选、游戏类别二次分类 | 专业／类别／搜索、未收录视图已实现 | 三客户端类别枚举、缓存、布局需验收 |
| 原生附件操作 | 右击切换、双击数量、一键添加、拖拽已实现 | 时光服拆分后的实际数量、满背包、延迟和多插件共存待确认 |
| 多客户端交付 | 共享代码，三客户端模拟 | 当前只部署时光服，不宣称其他当前版本游戏通过 |

## 建议的完成门槛

1. 时光服完成固定回归：首次打开、切发件箱、选角色、双重筛选、右击、部分数量、一键添加、关闭邮箱、重载读回用户规则。
2. 多插件共存及UI缩放可用，附件数量／原有附件／收件人正确，无自动发送。
3. 明确记录已知数据缺口和各客户端验证状态，再决定线上版本、Tag和发行说明。

## 后续可选功能，尚未实施

优先考虑两项：**每个物品保留数量**（给当前角色留材料，避免一键全部转走）和**用户规则导入／导出**（跨账号备份与分享）。它们直接改善当前邮寄流程，但不是最初核心范围的完成前置条件。

可以再考虑发送前的简短核对摘要，但不要重新加入用户已要求移除的重复附件网格。专业用品数据补齐属于持续维护，而不是无限增加新功能。

暂缓AI运行时接入、拍卖功能、通用批量收信和自动发送。先验证已有操作的准确性与稳定性，再按实际使用反馈选择下一项。

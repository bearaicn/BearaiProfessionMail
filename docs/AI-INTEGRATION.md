# AI 模型接入可行性记录

日期：2026-11-04。用户询问插件能否调用模型接口；本轮仅研究并记录，没有实现网络调用、外部程序或数据上报。

## 技术边界与建议

当前标准 WoW AddOn Lua 环境不提供通用 HTTP／Socket 客户端；不能直接请求外部模型接口，包括 localhost。插件消息用于游戏内通信，不是任意网络接口。不要假定时光服／无限服存在额外网络 API，除非后续获得该客户端的明确接口证据。

可行方案为游戏外工具调用模型，游戏内接收结构化结果：

1. 插件提供可复制的物品 ID、名称、客户端版本和待分析内容；用户手动复制。
2. 外部网页／桌面工具请求模型，模型凭据留在外部工具中。
3. 用户将返回的结构化规则粘贴到插件导入面板；插件按允许的字段校验、预览后由用户保存为用户规则。

此方案无需实时文件桥，也不把外部结果作为可执行 Lua 运行。导出／导入 UI 和外部工具目前均未实现。

另一种较重的方式是桌面程序生成一个事先约定的独立数据文件，通过插件启动／重载加载；需要额外的同步协议和版本校验。不能宣称游戏能实时读取任意文件，不能在游戏运行时通过覆盖其 SavedVariables 文件来同步，否则旧内存数据可能覆盖外部改动。

TSM 的第一方说明中可看到“桌面应用＋AppHelper＋游戏内 /reload”这种外部数据配合方式：[TSM 官方排查说明](https://support.tradeskillmaster.com/en_US/addon/why-dont-i-see-any-pricing-in-my-item-tooltips)。这只是架构参考，不代表本项目已复用其实现或完成类似桥接。

## 对本插件的适用场景

- 为未收录物品提供专业归属候选或解释；保留物品 ID、客户端与证据，人工核对后存入用户规则。
- 辅助整理材料数据、发现疑似遗漏或服务器差异。
- 不用模型替代确定性的背包扫描、专业匹配和邮寄限制判断，也不让模型自动操作邮件发送。
